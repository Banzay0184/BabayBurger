# Исправление проблемы с фильтрацией заказов по регионам

## Проблема

Заказы из других регионов (например, Каган) приходили к оператору Бухары через WebSocket, но после обновления страницы исчезали из списка заказов.

## Причина

1. **WebSocket отправлял заказы всем операторам**: В сигналах Django заказы отправлялись в общую группу 'operators', поэтому все операторы видели все заказы в реальном времени.

2. **Фильтрация происходила только при загрузке**: При обновлении страницы `get_queryset()` фильтровал заказы по зонам доставки, поэтому заказы из других регионов исчезали.

## Решение

### 1. Изменена логика WebSocket уведомлений

**Было:**
```python
# Отправляем всем операторам
async_to_sync(channel_layer.group_send)(
    'operators',
    {
        'type': 'order_created',
        'order': order_data,
        'timestamp': timezone.now().isoformat()
    }
)
```

**Стало:**
```python
# Отправляем каждому подходящему оператору индивидуально
for operator in suitable_operators:
    async_to_sync(channel_layer.group_send)(
        f'operator_{operator.id}',
        {
            'type': 'order_created',
            'order': order_data,
            'timestamp': timezone.now().isoformat()
        }
    )
```

### 2. Улучшена фильтрация в get_queryset()

**Было:**
```python
# Фильтрация только по городу
queryset = Order.objects.filter(
    address__city__in=operator_zones.values_list('city', flat=True)
)
```

**Стало:**
```python
# Фильтрация по городам + дополнительная проверка координат
operator_cities = list(operator_zones.values_list('city', flat=True).distinct())
queryset = Order.objects.filter(
    status__in=['pending', 'confirmed', 'preparing', 'ready', 'on_delivery'],
    address__city__in=operator_cities
)

# Дополнительная фильтрация по точным координатам зон
filtered_orders = []
for order in queryset:
    can_handle, _ = operator.can_handle_order(order)
    if can_handle:
        filtered_orders.append(order)
```

## Результат

1. **Заказы показываются только подходящим операторам**: WebSocket уведомления отправляются только операторам, которые могут обработать заказ.

2. **Консистентность данных**: Заказы не исчезают после обновления страницы, так как фильтрация одинаковая в WebSocket и при загрузке.

3. **Точная фильтрация по зонам**: Используется метод `operator.can_handle_order(order)`, который проверяет точные координаты зон доставки.

## Тестирование

### Проверка WebSocket уведомлений
1. Создайте заказ из региона Каган
2. Убедитесь, что заказ приходит только к оператору Бухары (если у него есть зона Каган)
3. Убедитесь, что заказ НЕ приходит к оператору из другого региона

### Проверка фильтрации при загрузке
1. Создайте заказ из другого региона
2. Обновите страницу оператора
3. Убедитесь, что заказ остается в списке (если оператор может его обработать)
4. Убедитесь, что заказ НЕ появляется у оператора из другого региона

### Проверка логирования
В логах должно быть:
```
📡 Sending WebSocket notification to operator 123 for order #456
WebSocket уведомление о новом заказе #456 отправлено 1 операторам
```

## Файлы изменены

- `backend/app_operator/signals.py`: Изменена логика WebSocket уведомлений
- `backend/app_operator/views.py`: Улучшена фильтрация в `get_queryset()`

## Заключение

Проблема с заказами из других регионов полностью решена. Теперь заказы показываются только тем операторам, которые могут их обработать, как в реальном времени через WebSocket, так и при загрузке страницы.
